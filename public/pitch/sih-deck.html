ECDAT
Enterprise Cryptographic Discovery & Analysis Tool

Static inventory of crypto primitives in LLVM IR and stripped binaries — no execution, no evasion kit.

Problem

  • Enterprises ship unknown crypto: weak MD5/SHA-1, table AES, RSA modexp.
  • Firmware and vendor blobs hide algorithms behind stripped symbols.
  • Security teams need evidence-backed inventory, not guesswork.

Three-channel architecture

① IR signaturesFIPS/RFC constant tables in Clang LLVM IR (.ll)
② CFG softmax modelLogistic regression on opcode/graph features; trained on clean + mutated IR
③ Raw byte scanS-box, K[], ChaCha sigma, HMAC ipad/opad in ELF/PE images
drop .ll / .o → parse & classify → fuse findings → enterprise inventory (JSON/HTML)

Catalog (today)

  • AES, AES-GCM, SHA-256/1, MD5, HMAC-SHA256, ChaCha20, Curve25519, RSA-modexp/key, TLS, DRBG
  • ELF · PE · stripped .o/.so — byte scan without symbols
  • Weak/deprecated flagged · verify:all + vendor holdout green

Live demo path (~2 min)

  1. Load Enterprise mix (IR) → AES + SHA-256 + ChaCha + MD5 + RSA-modexp
  2. Click weak MD5 finding → constant-table evidence
  3. Load Stripped vendor AES (.o) → S-box at file offset, no symbols
  4. Load PE firmware blob → AES + TLS on Windows-style image
  5. Load Stripped enterprise mix (.o) → multi-primitive byte scan
  6. Inventory → tag asset / business unit → Export JSON

Differentiators

  • LLVM + AI story: signatures + independent CFG model corroboration
  • Works on stripped real binaries, not just named lab IR
  • Enterprise inventory export with severity + recommendations
  • Honest static scope — inventory, not malware or packing

Roadmap (post-SIH)

  • PE / firmware lift to IR when bitcode unavailable
  • OpenSSL / libsodium IR in training holdout (wild validation)
  • TLS stack fingerprinting, key-length heuristics, org asset tagging
